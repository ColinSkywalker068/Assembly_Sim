# 2026-10-18：官方生产入口、断裂面诊断与完整候选筛选

本轮完成生产入口的官方预处理接入与两批候选几何筛选，并找到了头骨断裂特征失配的强证据。**真实头骨自动物理装配仍未通过；本轮没有执行机械臂装配轨迹。**

## 生产预处理

`tools/official_backend.py` 直接调用固定 GARF commit 的 `MeshInferenceDataset`，避免复制一套近似公式。使用独立局部米制 mesh，显式指定每个模型单位对应的米数；后端不读取 assembled GT。

| 阶段 | 现在的默认入口 |
|---|---|
| 采样 | 官方 uniform surface sampler，5000总点数，面积加权，最低20点，尾数补到最大片 |
| 共同尺度 | 官方 `max(1, max mesh extent)`，先按显式 model_unit_m 转为模型单位 |
| 逐片变换 | 官方中心化、随机旋转、max(abs)归一化；法向用同一旋转 |
| 锚点 | 当前输入几何的局部中心与逆增广旋转，不使用装配真值 |
| 推理 | app exponential scheduler，20 steps × 6 iterations，wxyz |
| 恢复 | 完整恢复增广、局部中心和米制尺度 |
| 多noise | 几何seed=42，编码器seed=42，并缓存同一latent；只改变初始位姿噪声 |

固定几何随机源、缓存特征是为隔离noise而保留的明确差异；官方app默认会把同一个seed用于几何与噪声。底层预处理算法直接来自官方源码，不代表所有上游运行的逐位GPU输出相同。

设原局部点为p，共同物理尺度为s，官方中心为c（模型尺度下），随机增广为Q，逐片尺度a：`u = Q(p/s-c)/a`。模型给出R,t后，局部mesh位姿恢复为：

```
R_local = R @ Q
translation_m = s * (t - R_local @ c)
```

官方返回quaternion是Q的逆，因此实现使用 `R @ augmentation_inverse.T`。加入随机非零中心、不同旋转与米尺度的回归测试。任务和core共53项测试通过（含排序指标tie处理回归）。

默认CLI要求 `--mesh-registry` 和 `--model-unit-m`；没有完整表面/面积信息的无组织点云，无法与mesh面积采样严格等价。当前NPZ用于注册ID和已有工具协议，权威推理点云由同局部坐标的注册mesh生成。旧按点数密度采样的路径只有显式 `--legacy-preprocessing` 才启用。不是默默把未标定点云当成官方输入。

本次模型单位为0.20749005075939986 m，来自此样例最长边缩放为200 mm的实验设置，不能视为原始头骨实测尺寸。输入、权重和源码哈希沿用上一轮审计manifest。几何筛选加速环境安装rtree 1.4.1、embreex 4.4.0。

## 断裂面诊断

以离线GT下距离<1 mm且相邻表面法向点积<-0.5作为**几何接触代理标签**，并以官方0.5概率阈值二值化断裂面预测。这不是人工语义断裂面GT；头骨窄间隙、接近面和采样分辨率可能影响指标。

| 数据 | 精确率（微平均） | 召回率（微平均） | F1 |
|---|---:|---:|---:|
| 真实八片头骨 | 39.83% | 8.01% | 13.33% |
| 官方12片瓶子 | 99.79% | 99.93% | 99.86% |

头骨最大片3512个采样点中，几何代理接触点424个，预测为断裂面的5个点全部不在代理接触区：召回率0。另两片召回率也为0，其他多片明显漏检。相同方法在瓶子上几乎恢复全部接触区域。这支持“预训练编码器/断裂特征对该头骨几何泛化不足”，比仅凭大位姿误差更有定位价值。

但**不能宣称已证明唯一因果根因**：`DenoiserBase._extract_features` 仅取 `feature_extractor(...)["point"]`，没有使用 `coarse_seg_pred` 来筛除点；分类头只是共享编码器的诊断信号。仅替换断裂面分类输出不会改变当前位姿网络输入。瓶子分割接近完美，仍有部分位姿失败，也说明分割准确不等于装配准确。

下一步应该用多件头骨、按物体划分的训练/验证集评估并适配encoder/denoiser；不能在这一个测试头骨上拟合后声称泛化成功。另需诊断接触几何曲率、对称性和薄壳结构，验证错误是否来自训练分布与特征表达。

补充阈值无关诊断，排除“只需调低0.5阈值”的解释：

| 数据 | ROC-AUC | Average Precision | 正例比例（AP基线） |
|---|---:|---:|---:|
| 头骨 | 0.5359 | 0.2613 | 0.2398 |
| 瓶子 | 0.9985 | 0.9980 | 0.5730 |

头骨预测排序接近随机；扫描阈值0.001–0.9，最高F1仅0.1468，阈值0.001时召回率9.01%。这不是简单的0.5阈值校准问题。未把离线GT挑出的阈值写入部署设置。指标来自`fracture_thresholds.py`，处理相同分数的ties，详见两份`*_thresholds.json`。

## 位姿与筛选结果

统一将整件最长边设为200 mm。新入口四个noise的非锚点平均位置误差为98.60、82.39、116.20、91.31 mm，旋转误差为123.75、135.91、129.18、118.73°。完整输出见 `skull_metrics.json` 和 `skull_screened.json`。

全部候选、全部28个碎片对、双向表面及内部探针检查已经完成，每片256个样本；这仍是采样式几何拒绝检查，不是连续碰撞或路径可行性证明。

## 复现

```sh

  --repository /path/to/GARF --checkpoint /path/to/GARF.ckpt \
  --source /path/to/view_gt.glb --output /path/to/audit
```

## 自动装配状态

生产链路停在几何拒绝阶段：`geometry_status=all_candidates_rejected`，`selected_candidate=null`，`motion_authorized=false`。没有把最低分的失败候选交给机器人，也没有用GT替换预测来宣称自动装配成功。仍待完成的独立环节包括制造体素拓扑、实际夹爪资产、受约束IK/规划、物理夹持、释放后稳定性和RGB-D身份/位姿估计。


实际JSONL S2入口也完成GPU集成验证：`tool_integration.json`记录 `official_MeshInferenceDataset`、注册mesh哈希、几何拒绝和`motion_authorized=false`。集成验证的独立模型加载可能有GPU非确定性，不能把它与同latent的多noise实验混为一组。
